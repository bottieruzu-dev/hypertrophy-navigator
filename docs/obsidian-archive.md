# 運動・栄養・体の記録をObsidianへ残す

2026-10-15実装。原本はアプリとSupabaseです。Obsidianは読み返すための一方向の記録で、アプリの復元用バックアップや端末間の双方向同期とは別です。

## 保存するもの

- 全期間の筋トレ：セッション、準備を含む各セット、実績・目標・RIR・推定1RM、日別計画、Week0測定。
- 有酸素運動と、アプリの判定イベントの種類・理由。
- 確定した食事：食材・商品名・数量・単位・補足、34栄養素、根拠と仮定、保存時の目安。取り消し済みは履歴として残し、合計から除外します。計算待ち・未確定の下書きは含めません。
- 体重、体脂肪率、ウエスト、おへそ周り、肩・胸・腕・太ももの周囲、睡眠、回復度、保存済みの計算値・移動平均。
- 旧方式の栄養ログは別欄に残し、食事の摂取合計に二重加算しません。

認証情報、アカウントID、栄養プロフィール設定、未使用の食材辞書はノートへ出しません。現在のアプリに私的記録の入力機能はありません。将来取り込んだデータに `private: true` や `originKey` があれば、該当記録と参照する派生記録を生成対象から除外します。この対応だけで将来のあらゆるプライバシー形式を保証するものではありません。

指定先の中に次の構成で生成します。元の名称や自由入力はファイル名に使いません。

```text
workout tools/
  00_記録の索引.md
  日次/2026/10/2026-10-15.md
  月次/2026/2026-10.md
  年次/2026.md
```

日別は運動・栄養・測定を1ファイルにまとめます。月別・年別は、記録日数・完了した筋トレ回数・34栄養素の平均・体の最初と最後の測定差・日別へのリンクを残します。不明な栄養素を0で埋めず、成分ごとに平均の対象日数を明記します。食事のない日は平均の分母へ入れません。補間した体重などは測定差から除きます。

## 実行時刻とPC停止中の扱い

Windowsタスクを通常権限で登録し、毎日 **23:59（日本時間）** と **本人のログオン時** に受信します。予定時刻を逃した場合は `StartWhenAvailable` で利用可能時に実行します。PC停止中にファイルは書きません。スリープを強制解除する設定も加えません。

23:59より前に実行した場合は前日まで、23:59以降は当日までを対象にします。起動時に全期間を確認するので、何日PCを開かなかった場合でも過去分を取り込みます。過去の日付の修正・遅れて確定した食事も次の正常な受信で反映されます。

この時刻は **PCが受信する時刻** です。端末内にしかないデータをPCがスマホから直接取り出すことはできません。記録する端末ごとに、更新版のアプリで自動送信を有効にしてください。アプリが開いている間に変更後約2秒と失敗時の再試行で送信します。ブラウザーを閉じている間の送信は保証しません。23:59直後の修正・確定は次の受信に入る場合があります。

## 初回の設定（利用者が実行）

この開発環境では実データの取得、実クラウドへのSQL適用・関数公開、指定保管庫への書き込み、Windowsタスク登録は実行していません。保管庫は作業用の書き込み許可範囲外です。以下を本人の環境で実行してください。認証情報をAIへ渡す必要はありません。

### 1. Supabaseへ専用機能を追加

既存の同じプロジェクトを使います。`restore-owner-sync.sql` と `nutrition-work.sql` 適用済みが前提です。

1. SQL Editorで [obsidian-archive.sql](../supabase/security/obsidian-archive.sql) を実行。
2. [verify-obsidian-archive.sql](../supabase/security/verify-obsidian-archive.sql) を実行し、全項目が `true` であることを確認。
3. [test-obsidian-archive.sql](../supabase/security/test-obsidian-archive.sql) を実行。ダミーの送信・再送・競合・削除・不正認証を確認し、変更はすべてロールバックします。実記録を読み出す正常なexportはこのテストでは行いません。
4. 手元のSupabase CLIの通常の認証設定で、新しい関数だけを公開。

```powershell
Set-Location 'C:\Users\user\dev\hypertrophy-navigator'
node scripts/build-obsidian.mjs
supabase functions deploy workout-obsidian-export
```

CLI認証・プロジェクトの関連付けが未設定なら、本人がCLIの手順で設定してください。キーやアクセストークンをコマンド引数、チャット、Gitへ貼らないでください。通信や権限が拒否された場合に、制限解除や管理者実行で通さないでください。

`supabase/config.toml` のこの関数の `verify_jwt=false` は、PC専用ヘッダー認証に置き換えるためです。無認証で記録を読む機能ではありません。関数とSQLの認証チェックを一緒に適用します。ブラウザーやPCに管理キーは不要です。

### 2. アプリをVercelへ反映し、全履歴を送信

変更をレビューして通常のGit/Vercelの手順で公開します。検証用の `build:safe` 出力は公開用に使いません。依存の追加取得は不要です。

記録を持っているスマホ・PCそれぞれで、新版を開いて本人ログイン・端末の所有者登録を確認し、クラウド設定の **「全履歴を送信・自動送信を有効化」** を押します。これが過去分の取り込みと以降の自動送信の開始操作です。送信完了表示を確認してからアプリを閉じてください。

既にクラウドにある筋トレ・体組成・旧栄養ログも取得対象に含めます。手動の食事など、以前は端末内だけだった履歴は、その記録がある端末からの初回送信が必要です。過去に消した端末内データを新しく復元する機能ではありません。

### 3. PCの読み取り接続を設定

アプリの **「PCの接続情報を発行」** を押します。以前のPC用接続情報は無効になります。コピーする内容は秘密として扱い、PCの次の設定画面だけへ貼り付けます。

```powershell
Set-Location 'C:\Users\user\dev\hypertrophy-navigator'
node tools/obsidian/setup.mjs
```

表示された `http://127.0.0.1:.../` をこのPCのブラウザーで開きます。接続情報と、次の保存先を入力します。

```text
C:\obsidian\小竹隆のダッシュボード\AI_gogi\workout tools
```

認証と完全な取得ができることを確認してから設定を保存します。この段階ではノートは生成しません。接続設定は `%LOCALAPPDATA%\HypertrophyNavigatorObsidian\connection.json` に保存します。トークンはWindowsの本人アカウントに結び付くDPAPIで暗号化し、保管庫・Gitには置きません。別Windowsアカウントや別PCへ、この暗号化設定をそのままコピーする運用ではありません。接続情報は400日で期限が切れるため、継続利用時は再発行して設定し直してください。

### 4. 手動で受信してから、自動実行を登録

```powershell
node tools/obsidian/receiver.mjs --once
node tools/obsidian/receiver.mjs --status
```

当日分もすぐ確認したい初回のみ、次を使えます。通常の23:59受信では不要です。

```powershell
node tools/obsidian/receiver.mjs --once --include-today
```

指定フォルダーにノートができること、生成欄の外に書いた追記が残ることを本人が確認してから登録します。

```powershell
.\tools\obsidian\install.ps1
```

タスク名は `HypertrophyNavigatorObsidianArchive` です。Windowsのタイムゾーンが日本以外なら登録を止めます。OS設定を勝手に変更しません。既存の同名タスクも上書きしません。通常権限で「ログオンしているときのみ」、毎日23:59とログオン時、逃した時刻の実行、失敗時15分間隔で最大3回の再試行を設定します。実行時間上限は15分です。

実行ポリシーやタスク登録が拒否された場合、管理者実行や `ExecutionPolicy Bypass` で回避しないでください。手動受信は独立して利用できます。組織の許可範囲でタスクスケジューラから登録する場合も、上記の同名タスク・通常権限・同じ時刻と再試行設定を使い、操作は `node.exe` に絶対パスの `receiver.mjs` と `--once` を渡してください。許可されない場合は自動登録を未完了として扱います。

## 日々の確認と編集

- アプリ：記録保存用データをクラウドへ送った状態を表示します。
- PC：`node tools/obsidian/receiver.mjs --status` で最終成功日時・対象日・件数・ファイル数を確認できます。時刻はUTC表示、対象日は日本時間です。
- Obsidian：生成欄の外の「自分の追記」は自由に書けます。自動生成欄を手で変えた場合は、上書きを止めます。必要な内容を追記欄へ退避してから、変更前の生成欄へ戻してください。
- Git・他端末：既存のObsidian同期に任せます。この受信プログラムはcommit・pull・pushをしません。記録の機密性は既存同期先の公開範囲にも依存します。

受信状態・パス一覧・最終成功情報・ロックは、すべて保管庫外の専用状態フォルダーに置きます。記録本文をログや状態キャッシュへ保存しません。認証が失効したら、アプリで再発行してPC設定を再実行します。解除はアプリの **「PCの接続を解除」** を使います。解除しても既存のMarkdownやGit履歴は消しません。

二重起動はロックで止めます。異常終了でロックが残った場合のみ、次を実行します。保存されたPIDが存在しないことを確認した場合に限って、自分のロックを解除します。実行中のNodeを終了したり、他ツールのロックを触ったりしません。

```powershell
node tools/obsidian/unlock.mjs
```

Gitのマージ・リベース・index.lockなどがあればノートへの反映を見送ります。保管庫にジャンクション・シンボリックリンクがある場合や、`.git` がworktree用の間接ファイルの場合も追跡せず停止します。対応するためにリンクやACLを自動変更しません。

## 整合性と制限

- 同じIDは更新、別IDの同文は別記録です。過去の編集や日付変更も毎回全件から生成し直します。消えた記録の元ファイル全体は削除せず、生成欄を空の案内へ変え、手書きを残します。
- ローカルで以前送った記録が消えた場合は、明示的な削除マーカーを送ります。他端末にしかない記録を「この端末にない」だけで削除しません。
- 同じIDを別端末が異なる内容で更新した場合は、比較した改訂ハッシュが合わない送信を停止します。自動の後勝ちで消す運用にしません。これは複数端末の編集を自動マージする機能ではありません。競合時は原本のどちらを残すか確認してから個別に対応します。
- PCは、単一SQL文で作った整合した全件応答を最後まで受信・検証してから書きます。空応答・認証失敗・途中切断は既存ノートの消去として扱いません。最大10万レコード・応答20MBで、それを超えたら切り捨てず停止します。大量化した場合は固定スナップショットのページ取得へ拡張します。ブラウザーの1回の変更送信は10MBまでです。
- 生成欄はSHA-256を検証し、全対象を事前確認してから、一時ファイルを同じディレクトリ内で置換します。書く直前にも内容を再確認します。複数ファイル全体の一括置換ではありませんが、途中終了後は再実行で収束します。
- リンク・範囲外パスを拒否します。ただし、同じWindowsアカウントの悪意ある別プロセスが検査と書き込みの間にフォルダーを差し替えるような攻撃まで、通常のパスAPIで完全には防げません。
- 原本での非公開化・削除が反映されても、過去のGit履歴・バックアップ・他端末のコピーを自動削除しません。

## 開発時の検証

```powershell
node scripts/build-obsidian.mjs
node scripts/test.mjs
node tests/obsidian-files.test.mjs
node node_modules/typescript/bin/tsc -p tsconfig.tests.json
node node_modules/typescript/bin/tsc -p tsconfig.functions.json
node node_modules/oxlint/bin/oxlint

```

ダミーで、日付境界・全期間の集約・34成分の不明と0・取り消し・単位・再受信・日付変更・削除・私的派生記録・手編集・Git競合・範囲外パス・ジャンクション・二重起動・途中失敗・再開・認証拒否・秘密を本文に混ぜない処理を確認します。テスト用のファイルは `node_modules/.tmp` の隔離フォルダーだけへ書きます。実データや実保管庫は使いません。

この開発環境ではWindows暗号化用の子プロセス起動が `EPERM` で拒否されたため、DPAPIの往復テスト1件は未実行として明示的にスキップします。権限拡大や別経路での再試行はしていません。利用者の通常環境で同じダミーテストを実行して確認できます。

未確認：Windows暗号化の実機往復、実SupabaseでのSQL実行とEdge応答、新版ブラウザーからの送信、実保管庫への保存、23:59・ログオン・スリープ復帰での起動、既存Git同期・別端末の表示。これらはコードのテスト成功とは区別してください。
