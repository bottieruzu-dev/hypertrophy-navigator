# 栄養ページの使い方と検証範囲

## 初回設定

栄養ページで年齢・身長・初期体重・食事摂取基準の性別区分を保存します。個人情報をソースやGitに埋め込まず、端末内で管理するための設定です。対応範囲は18〜49歳の一般成人です。妊娠・授乳や医療上の栄養制限の個別計算には対応していません。

体組成ページの「選択日以前の最新の実測体重」を使って、タンパク質目標を体重kg×2.0gから1g単位で四捨五入します。体重がない場合だけ初期体重を使い、未来・補間・0・不正な値を除外します。7日平均も表示します。過去の食事には保存当時の目標を保持し、過去日の集計画面ではその日の最初の有効な食事記録の目標を使います。

カロリーはMifflin–St Jeor式による安静時代謝推定×活動係数から減量幅を引いた開始値です。活動係数1.55、減量幅15%が初期の運用設定で、測定された消費量ではありません。手動のカロリー設定もできます。脂質はカロリーの25%、炭水化物はタンパク質と脂質を引いた残りをg換算します。短期の体重変動だけを理由にカロリーを大きく変えず、実際の推移を確認してください。

## 日々の入力

1. 記録日と朝食・昼食・夕食・間食を選ぶ。
2. 食材欄を開き、登録済みの食材を選ぶか、新規入力する。
3. 商品名・補足・量を量った状態を入力する。商品名と補足は任意。
4. 「重量（g）」か「個数（個）」のどちらか一方を入れて一覧に追加する。個数だけなら重量は不要で、例えば個数欄の1は1個として保存する。片方の入力で他方は空になる。追加前の量の表示と一覧の単位を確認する。食材として登録すると次回の候補に残る。
5. 一覧を確認し「栄養計算用プロンプトをコピー」。依頼と入力途中の一覧は端末に保存される。
6. ChatAIへ貼り付けてJSONを受け取る。今回の食材の栄養だけを回答する形式になっている。
7. 同じ依頼を選び、JSONを貼り付ける。数量、可食部重量、根拠、仮定、栄養値を確認する。
8. 確認チェックを付けて「この食事分を追加」。貼り付けだけでは摂取量に加算しない。

夕食を分けて入力する場合は、それぞれ別の依頼を作ります。累計はアプリが計算し、AIの会話履歴に依存しません。同じ依頼を再保存しても二重加算しません。コピーがブラウザーから許可されなかった場合は、表示されたプロンプトを手動でコピーできます。日付が変わっても編集中の日付を保ち、「今日に移動」で切り替えます。

## 修正と取り消し

栄養値だけを直す場合は履歴の「栄養JSONを修正」を使います。上書き保存で、元の栄養を重ねて加算しません。

食材や数量を直す場合は「食材・数量を修正」。一覧を修正して再度AIへ計算を依頼します。新しいJSONを保存するまで元の食事分を保持し、保存時に同じトランザクションで置き換えます。別画面などで元の記録が更新されていた場合は置き換えを中止します。

「この記録を取り消す」は記録を残したまま集計対象から外します。「取り消しを戻す」で復元できます。置き換え前の記録を戻す場合は、先に置き換え後の記録を取り消して二重集計を避けます。

## 栄養と不明値

基本9項目、ビタミン13項目、ミネラル12項目、計34項目を表示します。食塩・飽和脂肪酸は抑える方向、食物繊維・カリウムは目標量、それ以外は推奨量・目安量等の区別を表示します。耐容上限量は摂取目標にしません。型・単位・食材照合の検証は行いますが、AIの数値や出典が正しいことをアプリが確認したという意味ではありません。

不明な値は`null`で保持し、0と区別します。「既知分100mg・1品不明」のように表示し、不明が残る場合は目標との差を確定した不足量として表示しません。未記録の食事がある可能性にも注意してください。

直近7日の平均は「記録がある日」で計算し、未記録日は0としません。不明な栄養値がある場合は既知分の平均と不明の品数を示します。一日の不足や平均値だけで欠乏症を診断するものではありません。

## 食事改善の相談

「食事改善プロンプトをコピー」で、目標、プロフィール、参照体重、選択日の食材と量、既知分の栄養、不明項目、直近14日以内の体重と腹囲をまとめます。コピー後に全文が表示されます。含まれる内容を確認し、自分でChatAIへ貼り付けてください。アプリから外部AIへ自動送信しません。

AIには「今日追加する食材と量」「次回の置き換え案」を分けて、カロリー・PFC・食塩などを考慮した提案を依頼します。不明を不足と扱わず、一日ですべての差を無理に埋めないように指定します。

## 保存とバックアップ

DB version 3で食材・依頼・食事記録用テーブルを追加し、既存の筋トレ・Week0・体組成・旧栄養記録を維持します。旧クイック記録は内訳不明の旧記録として表示し、新しい集計に自動で加算しません。

手動で追加した栄養記録は端末保存です。追加実装のWork経由の依頼・下書き・確定食事は、[栄養Work連携の適用手順](nutrition-work.md)に沿ってクラウド同期できます（実サービスへの適用は別途必要）。栄養ページのバックアップは食材・依頼・食事・プロフィール・入力途中の一覧・旧栄養記録・Workの計算待ちを含みます。体組成と筋トレは含みません。既存の筋トレバックアップにも栄養は含まれません。

復元は既存のプロフィール・入力途中の一覧を優先し、同じIDの異なる履歴は上書きせず全体を取り消します。同じバックアップの再取り込みで履歴を重複させません。同じ端末・ブラウザー・URLで利用し、データ消去や移行前にバックアップを保存してください。

## 検証状況

ダミーデータで筋トレ34件・栄養16件の自動テスト、型チェック、検証用ビルドを実行。既存の体組成ページにlint警告が1件、既存の主JSバンドルに500kB超のビルド警告が残っています。

`tests/ui.html`には隔離DBで旧version 1からversion 3への更新、旧栄養記録の保持、重複保存、修正、置き換え、復元の取り消し、再読込を検証するテストを追加しました。ただし、この作業環境には操作可能なブラウザーがないため実行できていません。画面・実IndexedDB・クリップボード・スマートフォンの操作は未確認です。

公開先の更新やGit pushは行っていません。`build:safe`の出力はクラウド設定を読み込まない検証専用です。通常の公開には通常の`build`を使い、設定はユーザー自身が管理してください。
