# 今夜の調整ごはん

筋肉を維持しながら減量する目的で、毎日22時（Asia/Tokyo）に夕食全体を3案生成し、栄養ページへ表示する機能です。電子レンジのみ・準備を含め30分以内、コンビニ食品とBASE FOODも候補にできます。アレルギー・避ける食品なし、予算上限なしという今回の設定です。提案は摂取記録に自動加算しません。

## 構成と使い方

1. 本人としてログイン・端末の所有者登録を行い、栄養プロフィールを設定する。
2. アプリが表示中は、プロフィール・直近30日の確定済み食事・体組成・筋トレを献立専用のprivate領域へ同期する。栄養ページの「今日の情報を同期」でも送れる。既存body_metrics等の通常同期とは別の、献立用スナップショットである。
3. 同期成功後は、スマホの画面を閉じても最後の同期情報を参照できる。ただし閉じた後の端末だけの変更は送られない。Workの確定・取消はサーバー側の記録を優先する。
4. PCとCodexが動作していればローカルのスケジュールからSupabaseプラグインを使用。22:00:00以上22:01:00未満に開始できた場合だけ生成し、22:30未満に保存する。時間外の開始、過去日、重複、生成中の元データ更新は保存しない。厳しい開始窓のため起動・認証に時間がかかった日もスキップしうる。
5. 栄養ページで選択した日の提案を表示し、30秒ごと／再表示時／「提案を更新」で再取得する。これは保存済み提案の取得であり、生成のやり直しではない。後から食事記録を変更しても、作成時点の提案として残る。

別端末の古いスナップショットが上書きしないよう、同期の版を比較します。競合したら最新の記録がそろっている端末で、クラウド設定の「この端末を送信元にする」を押してください。この操作は献立用の送信元を切り替え、筋トレや食事そのものを削除しません。

## 推定の扱い

- 当日確定済みの食事だけで34栄養素の既知分・不明数を集計する。未記録はゼロ摂取ではない。
- カロリーとタンパク質は既存の栄養目標の計算を使う。最新の実測体重がなければ設定済み初期体重を使用し明示する。現在のプロフィール計算の対象範囲は18〜49歳のまま。
- 体脂肪率・腹囲は最後の実測日付き参考値を使用し、根拠がある推定だけ仮定として説明する。データがない場合に数値を作らない。全身の体脂肪率から皮下脂肪量を測定したことにはしない。
- 栄養の概算は利用可。商品未指定の値を精密な商品ラベルとして扱わない。根拠、分量、調味料、調理条件、古い情報を説明し、推定不能な値はnullにする。
- 一晩ですべての差を埋めない。食塩・飽和脂肪酸等も考慮し、カロリー目標自体は自動変更しない。

## 適用

既存の所有者登録・nutrition-work.sql適用済みプロジェクトが前提です。

- `supabase/security/dinner-suggestions.sql`：新規privateテーブル2個と献立専用関数。既存データ・OAuthクライアント・認証設定は変更しない。
- ブラウザー向け3RPCは既存の本人＋通常ブラウザーログイン確認を使用。匿名・別人・既存栄養OAuthトークンは利用不可。
- タスク向け内部関数はSECURITY INVOKERかつpostgres管理接続限定。anon/authenticated/service_roleへは実行権限を付けない。Supabase管理プラグインの広い権限をタスクの指示で献立操作に限定する。
- `npm run build:dinner`：APIキー不要のローカルworkerを生成。タスクに[専用指示](dinner-automation.md)を保存する。新しいOpenAI APIの課金接続は不要。
- アプリは通常のVercel公開設定でビルド。`build:safe`はクラウド接続を空にする検証用であり、そのまま公開しない。
- スケジュールを有効にする前に、公開アプリでプロフィール同期成功・空状態の表示・最初の夜の結果表示を確認する。

## 検証

`npm test`、`tsc -b`、`tsc -p tsconfig.tests.json`、`npm run lint`、`npm run build:safe`、`npm run test:offline`、`npm run build:dinner`。

SQLはdinner-suggestions.sqlの最後のCOMMITを除いたものにtest-dinner-suggestions.sqlを続け、一括トランザクションで検証できます。合成スナップショットで所有者確認・別人/匿名/OAuth拒否・競合・重複・古い生成・過去日の拒否を検査し、すべてROLLBACKします。保存経路のテストだけは関数の時刻を22:05に置換してから実行し、その関数定義の変更もROLLBACKします。本番には時刻上書きパラメーターはありません。

画面は`npm run test:browser`から`tests/dinner-preview.html`を開くと、架空の献立3案を確認できます。実食事のテストデータではありません。
